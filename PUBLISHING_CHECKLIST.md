# Publishing Checklist

This repository contains **starter code, not a claim of existing impact**. Complete the following before requesting public distribution.

- [ ] Review every file for private or employer-owned information.
- [ ] Install Flutter; run `flutter pub get`, `flutter analyze`, and `flutter test`.
- [ ] Run the demo and inspect mobile and desktop accessibility.
- [ ] Choose your GitHub username and replace `YOUR_USERNAME` placeholders in `pubspec.yaml` and README.
- [ ] Update project maintainer and contact details with information you are comfortable making public.
- [ ] Create a *new, public* `quizforge_ui` repository, only after deciding to publish.
- [ ] Commit source code and push to `main`.
- [ ] Enable GitHub Issues, private security reporting, and GitHub Actions.
- [ ] Check green CI before tagging `v0.1.0`. Only then use the tag in the README install sample.
- [ ] Add an authentic screenshot/demo, accurate release notes, and respond to real community feedback.
- [ ] Track fixes, releases, accepted contributions, and legitimate usage over time.

OpenAI's Codex for Open Source program may require documented, impactful open-source maintenance. A brand-new repository, even if polished, does **not** establish eligibility or guarantee a free Pro subscription. Apply only with truthful information about public maintenance history and project impact.
